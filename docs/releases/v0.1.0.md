Fathomgate v0.1.0 is the first tagged release. It closes M0, the pass-through milestone: `fathomgate` sits between an MCP client and one network MCP server and forwards everything faithfully.

**There is no policy enforcement in this release.** Every call reaches the upstream server as the agent sent it, and nothing is held, denied or audited on the way. `fathomgate serve` refuses `--policy`, `--inventory`, `--profiles` and `--audit` with exit 2 until M1 wires them in. Until then the upstream's own checks are the only ones there are, so log in to devices with a read-only account.

## What M0 delivers

- **A pass-through proxy.** `fathomgate serve --server <name> --upstream <path>` starts one stdio upstream and shows its tools to the agent as `<server>.<tool>` (for example `netdev-ssh-mcp.run_show_command`). Cancellation and progress reach the upstream and back. The upstream gets only an allow-list of `fathomgate`'s environment; secrets are passed by name with `--upstream-env-pass`, never on the command line (ADR 0017). When the upstream stops, its whole process tree stops with it (ADR 0021).
- **Both MCP eras.** `2025-11-25` (stateful sessions) and `2026-07-28` (stateless, with multi-round-trip requests), on each side independently: a 2026 agent can use a 2025 server and the other way round (ADR 0008, ADR 0014). Upstreams that never answer `server/discover` still start (ADR 0018).
- **stdio and a loopback HTTP listener.** By default `fathomgate` talks to the agent on stdio. `fathomgate serve --listen 127.0.0.1:<port>` serves Streamable HTTP at `/mcp` instead, on both loopback addresses, with named bearer tokens read from an owner-only file or `FATHOMGATE_LISTEN_TOKEN`, and requests with an `Origin` header or a non-loopback `Host` refused (ADR 0016, ADR 0023). There is no TLS, so the listener is for agents on the same machine. Give each agent its own token: an agent that crashed or restarted without ending its session gets straight back in, because Fathomgate closes that token's oldest idle session to make room (T0.57).
- **The official MCP conformance suite.** CI runs it on every pull request against the real `fathomgate serve --listen`, with go-sdk's conformance server as the stdio upstream, for both eras. Every check that does not pass yet is listed in `tests/conformance/baseline/` with the decision record or task that covers it.

The parts M1 and later wire into the proxy are already in the binary as stand-alone commands: `fathomgate policy test` and `policy eval`, `fathomgate redact`, `fathomgate audit keygen` and `audit verify`, and `fathomgate inventory import`.

## Install

Download the archive for your platform from this release, check it, and put `fathomgate` somewhere permanent:

```sh
# linux or darwin; amd64 or arm64
curl -LO https://github.com/fathomgate/fathomgate/releases/download/v0.1.0/fathomgate_0.1.0_linux_amd64.tar.gz
curl -LO https://github.com/fathomgate/fathomgate/releases/download/v0.1.0/checksums.txt
curl -LO https://github.com/fathomgate/fathomgate/releases/download/v0.1.0/checksums.txt.sigstore.json
# cosign v3; prints "Verified OK"
cosign verify-blob --bundle checksums.txt.sigstore.json --certificate-identity https://github.com/fathomgate/fathomgate/.github/workflows/release.yaml@refs/tags/v0.1.0 --certificate-oidc-issuer https://token.actions.githubusercontent.com --certificate-github-workflow-trigger push checksums.txt
sha256sum -c checksums.txt --ignore-missing      # macOS: shasum -a 256 -c checksums.txt --ignore-missing
tar -xzf fathomgate_0.1.0_linux_amd64.tar.gz fathomgate
sudo install -m 0755 fathomgate /usr/local/bin/fathomgate
/usr/local/bin/fathomgate version
```

On Windows, download `fathomgate_0.1.0_windows_amd64.zip` (or `windows_arm64`), `checksums.txt` and `checksums.txt.sigstore.json`, run the same `cosign verify-blob` command, compare `Get-FileHash -Algorithm SHA256` with the zip's line in `checksums.txt`, and unzip `fathomgate.exe`.

Then follow [docs/install.md](https://github.com/fathomgate/fathomgate/blob/v0.1.0/docs/install.md) to connect Claude Code, Claude Desktop or Cursor. Use the full path to `fathomgate` and to the upstream server in every client config: desktop apps often start servers without your shell's `PATH`.

Each archive holds the binary, `LICENSE`, `NOTICE`, `THIRD_PARTY_LICENSES/`, `TRADEMARKS.md`, `README.md`, the example policies, the server profiles and `inventory.example.yaml`. Binaries are built with `CGO_ENABLED=0` and `-trimpath` by go1.26.8, with go-sdk v1.8.0; `go version -m fathomgate` shows both.

Not in this release: a Homebrew formula and a published container image. The `Dockerfile` in the repository builds the distroless image (`nonroot`, no shell) if you want one now; run it with `--init`.

## Verify

- `checksums.txt` lists the sha256 of every archive and SBOM. It is signed with [cosign](https://docs.sigstore.dev/cosign/) keyless signing: `checksums.txt.sigstore.json` is a Sigstore bundle holding the signature, a short-lived certificate issued to this repository's release workflow at this tag, and the public transparency log entry. The `cosign verify-blob` command above (cosign v3) checks all three, then `sha256sum -c` checks each download against the verified list. If `cosign verify-blob` prints anything but `Verified OK`, do not use the download.
- Each archive has an SPDX SBOM next to it: `<archive>.spdx.sbom.json`.

## Security

The listener, the process-tree handling and the MRTR `requestState` sealing went through security review before this release; the fixes are under Security in [CHANGELOG.md](https://github.com/fathomgate/fathomgate/blob/v0.1.0/CHANGELOG.md). Three items stay open in the [threat model](https://github.com/fathomgate/fathomgate/blob/v0.1.0/docs/security/threat-model.md): another local user can take the listener's port while `fathomgate` is stopped (M1); prompt availability for stateful upstreams (M3); and the release job has no second-person approval yet, so the rule that only organisation admins can push a release tag is its only gate. Report a vulnerability as described in [SECURITY.md](https://github.com/fathomgate/fathomgate/blob/v0.1.0/SECURITY.md).

## What's next

M1, "Say no": `fathomgate` classifies each call (`READ_OPERATIONAL`, `READ_CONFIG`, `WRITE_CONFIG`, `EXEC_ARBITRARY` and the rest), resolves the device and its role, and decides `allow` or `deny` by your policy, naming the rule on every denial.
